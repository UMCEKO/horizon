Design: `DESIGN.md` §2.8. Needs SPEC-1 (`--routes-out`, `routing.json`), SPEC-2 (`Routing.confirm` lines) and SPEC-3 (`route!`, `route` bridge entries). Python plus a small Java change. ## 1. `tools/java_routing.py` (new)
Docstring first line: `W12's gates: which vanilla methods native routes to Java's merged method, checked against the routes reference packs need.`

Subcommands:
- **`gates [--check]`:**
  - Scan `crates/**/*.rs` for `route!(` invocations (the key is the 2nd argument, a string literal) and `gui_route!("key")` markers (W5). A regex is enough. Mark each row `game` or `gui` in a 4th column. Also scan `java_bridges!` entries that start with `route`, with `java_mods.py`'s existing entry regex: import it, don't copy it.
  - Write `mods/horizon/src/java-mods-host/boot/res/route_gates.tsv`: `key \t file:line \t enclosing fn`, sorted, header `# generated by tools/java_routing.py gates`.
  - `--check` exits 1 when the file differs from what it would write (CI freshness, as `test_animate_closure`).
- **`lint [--ledger]`** prints every failure, one per line, and exits 1 if any.
  1. **Unrouted keys:** every key in `tools/java_routing/packs/*.tsv` is gated (in the gate scan) or has a row in `tools/java_routing/deferred.tsv` (`key \t reason`). A reason must start with one of these, or the lint fails on it:
     - `worldgen: W10`;
     - `client: phase C`;
     - `view: <family>` (`entity`, `block_entity`, `scoreboard`, `save_stream`, `connection`);
     - `seam: lift`;
     - `seam: <file:line>` (a seam not done yet, with the site);
     - `special: <mechanism>` (`animate`, `item_code`, `sounds`);
     - `verdict: undecided`.
  2. **Gate checks:**
     - a gate key that is also deferred is an error ("remove the deferral"), except with a `seam: <file:line>` reason. That marks a port of the key that doesn't go through the gate yet (a partial seam), and the boot report shows it as `gated (partial: <n> sites)`;
     - a gated **edge** key (kind from the packs' TSVs) without a `route` bridge entry of the same owner, method and descriptor is an error;
     - a gate key in no pack TSV is reported as `stale gate`, and is an error unless the key appears in `tools/java_routing/test_routes.tsv` (keys the test mod routes; seeded with `Inventory#setSelectedSlot(I)V`).
  2b. **GUI markers:**
     - a `gui_route!` key must have a row in `mods/horizon/src/java-mods-host/**/gui_bridges.tsv` (W5's file; find it by name);
     - a `gui_bridges.tsv` row must have a marker;
     - GUI markers don't need a `route` bridge entry, and rules 3 and 4 don't apply to them.
  3. **Placement:** the `route!` must be the first statement of its fn, and the fn must be in an `impl Game` block (look back for the nearest `impl` line that names `Game`). If not, error `gate not first in a Game method`.
  4. **TAIL and early returns:** for a gated key whose TSV row has `tail = 1` and `returns > 1`, the body fn must contain at least one `route::early(`. The body fn is the call after the `route!`, read from the next statement, `self.<name>(`.
  5. **`--ledger`** (needs `.local/port-ledger/ledger.json`; skip with a message when absent):
     - for each gated key, every Rust fn the ledger lists as its port (`where`, `--json`) is either a fn holding the gate or its body fn, or its callers (ledger callers, `--json`) are only those fns. Otherwise: `<key>: native port <file:fn> bypasses the gate`;
     - for each gated key, every `overriders` entry with `super_call` in the latest `routing.json` (`--routing FILE`) whose class has a ledger port must have a gate of the same key in that port: `<key>: <subclass> super-calls it but its port has no gate`;
     - for each `verdict: undecided` deferral, report how many remain (not an error).
- **`report --routing FILE`:** a table for humans, `key | kind | family | mods | gated / deferred (reason) / UNGATED | needs_bridge`. Also add it to `replaces.md` (call it from `mod_replaces` when `routing` is present).

## 4. Boot report (`B/Routing.java`)
- `Routing.confirm` reads `route_gates.tsv` from the boot jar's resources (`Routing.class.getResourceAsStream("/route_gates.tsv")`; make sure `java_mods.py build` copies `boot/res/`, which it does for `animate_closure.tsv`).
- Each route line becomes: `Horizon: route <key> <edge|body> <on|off> <gated|UNGATED> (<mods>)`.
- After the lines, when any on route is ungated:
  `Horizon: <n> behaviours mods change won't take effect (native runs them without the mods' patches): <mod: Class.method, …>`.
  It's printed once, at `System.err`. Players' logs carry it, as the decision U2 asks.
- `routes.bin` doesn't change: an ungated route simply has no gate to resolve it.
