# API PR 2a replay and proof

Part of #1608. Run `python3 tools/refactors/api-pr2a/move.py` from an unmoved
checkout. It uses `git mv`, extracts generic registry code, rewrites direct callers,
updates manifests and source-path references, and formats only affected Rust files.
It accepts the player-residency slice's `attachments/resident.rs` when present.
It does not touch the typed Parts generator or the injection generators.

## Ownership

- `horizon-mod-runtime` depends only on `horizon-core`. It owns attachment storage,
  serialization, synchronization queues, publication/lifetime/observer primitives,
  the generic query index, registration requests, numeric name tables, dimension
  numbering and generic effect/block-entity registry resolution.
- API key newtypes, per-thread engine block mappings, typed Parts and dispatch stay
  in `horizon-mod-api`. Its public attachment names are re-exported from the runtime.
- The per-dimension index alias, handle construction, observers and Game tests stay
  in the game: they name `Game` or API handles. The reusable binding implementation
  becomes `AttachmentLifetime::bind<H>`; callers supply a resolved holder.
- World exports no compatibility attachment module. World, client, client-lib,
  render, protocol and mod-api have direct runtime dependencies. Client-lib builds
  the sources physically stored under horizon-client.

## Declared seam

`seam.json` records the exact old/new unmatched Rust-line multisets. It is not
regenerated by the move script or proof. Read it alongside the script. It covers:

1. Public visibility across the new crate edge and raw numeric slots instead of
   API key newtypes; wrappers in mod-api reconstruct the keys at their old boundary.
2. The generic lifetime binding method and its two caller changes.
3. Effect and block-entity lookup closures supplied by the game and test fixtures.
   The lookup loops, failure messages, ordering and numeric mappings are retained.
4. Dimension slot access through runtime functions, preserving the existing global
   table and its lock/slot behavior.
5. Identifier classification through the existing core `Identifier::parse_namespaced`
   rather than the package reader. It accepts the same nonempty namespace/path
   characters; its allocation is confined to registration, never a tick path.
6. The wasm source index's new runtime crate entry; generated bindings must follow
   attachment traits into their new owning crate.

New registry tests come from `registry_tests.rs` and are copied by the script.
They test request deduplication and diagnostics, accepted identifier boundaries,
lookup closures with registry ordering different from slot ordering, missing names,
and shared dimension numbering.

## Proof

Run `python3 tools/refactors/api-pr2a/moved_lines_check.py BASE`, with BASE the main
head used for the final replay. It compares complete attachment files byte-for-byte
(including their tests, excluding only the declared bind method), then compares the
multiset of Rust lines across *all* changed implementation files. Before comparing,
it normalizes crate paths, cross-crate visibility and rustfmt wrapping; it excludes
imports/module declarations, the new crate root, new tests and refactor tooling.
Only the exact residual lines in `seam.json` are permitted. No implementation is
excluded wholesale. The normalized seam must stay under 400 changed lines.

`--show-unmatched` prints residual lines for inspection; it never updates the
approved seam. A mismatch fails rather than silently accepting new edits.

Workspace checks, clippy and the wasm32 mod-api check belong to GitHub CI under the
room's policy, not a local pre-push CI run. Focused runtime, key and attachment tests
may run locally. No existing index benchmark is present in the initial source tree.
